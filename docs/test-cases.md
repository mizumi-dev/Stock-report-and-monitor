# テストケース一覧（JSTQB Test Analysis & Design）

`docs/requirements.md`の各項目をテスト条件に分解し、具体ケースに落とし込む。
実行結果は`docs/test-results/`に記録する。

凡例: 優先度 高=リスク高、中、低（`docs/test-plan.md`のリスク表に対応）

## A. 認証・アクセス制御（機能・セキュリティ）

| ID | 優先度 | 入力/手順 | 期待結果 |
|---|---|---|---|
| A1 | 高 | 正しいトークンでURLにアクセス | 登録フォームが表示される |
| A2 | 高 | トークンなしでアクセス | 操作不可（エラー/拒否） |
| A3 | 高 | 存在しない適当な文字列をトークンとしてアクセス | 操作不可（エラー/拒否） |
| A4 | 中 | Function URLのリソースポリシーを確認 | `lambda:InvokeFunctionUrl`と`lambda:InvokeFunction`の両方が許可されている（TODO#7で指摘の広さは別途記録） |

## B. 銘柄登録・削除（機能）

| ID | 優先度 | 入力/手順 | 期待結果 |
|---|---|---|---|
| B1 | 中 | 正常なティッカー(例: NVDA)を登録 | 一覧に追加される |
| B2 | 中 | 小文字や記号を含む不正なティッカーを登録 | `TICKER_RE`で拒否される |
| B3 | 中 | 登録済み銘柄を削除 | 一覧から消える |
| B4 | 中 | `MAX_WATCHLIST_SIZE`件登録済みの状態でさらに1件登録 | 上限エラーで拒否される |

## C. 期間モード切替（機能）

| ID | 優先度 | 入力/手順 | 期待結果 |
|---|---|---|---|
| C1 | 高 | SHORT/MID/LONGそれぞれに切替 | `app_settings.period_mode`が更新される |
| C2 | 中 | `app_settings`テーブル自体を読めない状況を想定 | 既定モード(MID)にフォールバックし画面が壊れない |

## D. シグナル判定ロジック（機能・回帰）

| ID | 優先度 | 入力/手順 | 期待結果 |
|---|---|---|---|
| D1 | 高 | 合成データでSHORTモードのRSI判定（当日値） | `judged <= 25`で買い、`>= 75`で売り、境界値も対称に判定 |
| D2 | 高 | 合成データでMIDモードのRSI判定（前週平均、休日を含む週） | 休場日を除いた実取引日数で平均される |
| D3 | 高 | 合成データでLONGモードのRSI判定（前月平均） | 前月の実取引日数で平均される |
| D4 | 高 | MID/LONGの出来高基準値 | 判定期間そのものを含めず、直前`volume_lookback`日間のみで計算される（自己参照がない） |
| D5 | 中 | SHORTの出来高基準値 | 従来通り当日を含む直近`volume_lookback`日平均 |
| D6 | 中 | トレンド判定（ゴールデンクロス/デッドクロス、並び順） | 実装変更なしのため既存動作を維持（回帰） |
| D7 | 低 | `_cycle_window`が空集合になるケース（データ不足） | 当日1件にフォールバックし例外を出さない |

## E. 選定レポート送信頻度（機能・回帰）

| ID | 優先度 | 入力/手順 | 期待結果 |
|---|---|---|---|
| E1 | 高 | SHORTモードでEventBridge相当のペイロードをinvoke（任意の曜日） | 選定レポートが送信される |
| E2 | 高 | MIDモードで`weekday=月曜`相当をinvoke | 選定レポートが送信される |
| E3 | 高 | MIDモードで`weekday=月曜以外`相当をinvoke | 選定レポートは送信されず、監視レポートのみ送信される |
| E4 | 高 | LONGモードで`月初の月曜(day<=7)`相当をinvoke | 選定レポートが送信される |
| E5 | 高 | LONGモードで`月曜だがday>7`相当をinvoke | 選定レポートは送信されない |
| E6 | 高 | 全モード共通：監視レポートは毎回送信されるか | どのモード・曜日でも監視レポートは送信される（登録リストが空でない場合） |
